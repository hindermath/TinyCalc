## Regeln und Durchführung / Rules and execution

Additive Task-ID `T014A` wird zwischen T014 und T015 eingefügt; bestehende IDs bleiben unverändert. Das Format `Tnnn` erlaubt dafür einen optionalen Großbuchstaben-Suffix. / Insert additive T014A before T015 without renumbering existing IDs; the format permits an uppercase suffix.

Eine Vertrags-ID bezeichnet eine stabile fachliche Pflicht; ein Pfad bezeichnet eine einzelne Eingabe in ihrem Kontext. Ein Gate ist eine Prüfschranke. Rot–Grün–Refactor bedeutet: erst den fachlich scheiternden Test belegen, dann minimal korrigieren, dann ohne Verhaltensänderung aufräumen. Infrastrukturfehler zählen nicht als fachliches Rot; bereits passende Fälle müssen nicht künstlich verschlechtert werden. Jeder spätere Produktfix benötigt den vorherigen roten Defekttest. Nachweise werden unter `specs/006-tui-functional-contract/evidence/` erzeugt, niemals jetzt als bestanden erfunden.

*Contract IDs represent stable obligations; paths represent individual contextual inputs. A gate is a checkpoint. Test-first work records a genuine failing regression before a minimal fix and behaviour-preserving refactoring. Infrastructure failures are not functional red tests; already correct cases need no artificial failure. Evidence is future output, not fabricated current proof.*

Format: `Tnnn`, optional `[P]`, optional `[USn]`, Tätigkeit mit Zielpfad und Abschlussbedingung. `[P]` bedeutet nur konfliktfreie Arbeit an getrennten Dateien nach erfüllten Vorgängern, keine Erlaubnis für autonome Agenten. Die vier Stories entsprechen US-001 bis US-004. Gemeinsame Version-, Vertrags-, Workflow- und Statistikdateien sowie globale Terminal.Gui-Sitzungen werden seriell bearbeitet. Vor jedem späteren Build/Test OS prüfen und den Buildzähler in `Directory.Build.props` bei gleichen Version/AssemblyVersion/FileVersion erhöhen; vor genehmigtem Commit auf nummeriertem Branch Minor 6 und tatsächliche Branch-Commitzahl binden.

*IDs are sequential; P marks conflict-free work only, not delegated execution authority. Stories map to US-001–004. Serialize shared artifacts and framework sessions. Apply OS, build-counter and numbered-branch version rules before future build/test/commit actions.*

Reihenfolge bleibt **Migration → Funktionsabnahme → A11Y → Rename**. Kein PL/0, `.MCS`-Import, Formelkopieren, strukturelles Einfügen/Löschen, Scancode-Emulation, Runtime-Wechsel oder automatisches Paketupgrade. Ein vertikaler Slice ist nur ein Zwischenbeleg, niemals reduzierte Feature-Abnahme. C#/.NET ist MSL; kein Nicht-MSL-Ausnahmeprofil nötig. Die TinyCalc-Registry in `constitution.md` und `.specify/memory/constitution.md` bindet vier bestehende Projekte, .NET 10, xUnit, Smoke, DocFX-A11Y und Statistikreferenzen 80/125.

*Preserve series order and all non-goals. A vertical slice is interim proof, not reduced acceptance. C# is memory-safe and the existing TinyCalc registry remains binding.*
